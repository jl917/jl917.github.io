flex-grow, flex-shrink, flex-basis는 각각 무엇인가요?

flex는 flex-grow · flex-shrink · flex-basis를 한 번에 지정하는 축약 속성이며, 값을 선언하지 않으면 기본값인 0 1 auto가 적용된다.

  • flex-grow: 남는 공간을 얼마나 나눠 가질지 정하는 확대 비율이다. 기본값 0이면 공간이 남아도 늘어나지 않는다.
  • flex-shrink: 공간이 부족할 때 얼마나 줄어들지 정하는 축소 비율이다. 기본값 1이면 공간이 모자랄 때 함께 축소된다.
  • flex-basis: flex-grow/shrink를 적용하기 전, 아이템의 기준(초기) 크기다. auto면 width/height 값을, 지정하지 않았다면 콘텐츠 크기를 기준으로 삼는다.
flex: 1은 어떤 뜻인가요?

flex: 1은 타요소의 사이즈에 영향을 주지 않는 선에서 여유의 공간을 가져 가겠다는 뜻으로 해석이 되구요.

요소중 inline요소랑 block요소의 차이점이 무엇인가요?

inline은 기본적으로 요소의 줄바꿈 없이 처리한다. block은 줄바꿈 된다.

inline은 내부요소에 inline만 포함 할 수 있다. block은 inline, block 전부 포함한다.

inline은 크기가 내부 요소의 영향을 받고 지정할수 없다, block은 크기를 지정 할 수 있다.

inline은 좌우 margin, padding 만 처리 가능하고 block은 상화좌우 전부 가능하다.

JavaScript는 왜 Event Loop가 필요한가?

Event Loop는 JavaScript의 Call Stack이 비었는지 지속적으로 확인하고, 비어 있으면 먼저 Microtask Queue(Promise, async/await)를 모두 처리한 뒤 Task Queue(setTimeout, DOM 이벤트 등)의 작업을 Call Stack으로 이동시켜 실행하는 메커니즘입니다. 이를 통해 싱글 스레드 환경에서도 비동기 작업을 효율적으로 처리할 수 있습니다.

js에서 요청을 어떻게 취소 하나요?

new AbortController() 생성해주고 요청시 signal을 추가하고 abort()함수를 실행하면 된다.

// XHR
const xhr = new XMLHttpRequest();
xhr.open('GET', '<http://127.0.0.1:3000/api/get>', true);
xhr.send();
setTimeout(() => {
	 xhr.abort();
}, 1000);

// FETCH
const controller = new AbortController();
void (async function () {
    const response = await fetch('<http://127.0.0.1:3000/api/get>', {
        signal: controller.signal,
    });
    const data = await response.json();
})();

setTimeout(() => {
    controller.abort();
}, 1000);

// AXIOS
const controller = new AbortController();
const API_URL = '<http://127.0.0.1:3000/api/get>';
void (async function () {
    const response = await axios.get(API_URL, {
        signal: controller.signal,
    });
    const { data } = response;
})();
setTimeout(() => {
    controller.abort();
}, 1000);

promise, async/await, generator 어떤 연관이 있고 어떤 차이점이 있나요?

연관성

  • async/await는 generator + promise 기초로 만들어 졌고
  • async함수 실행시 Promise 를 return 되고, await는 Promise실행 성공할 때 까지 멈춘다.
  • Promise는 pending, fulfilled, rejected 상태를 가지고 처리 한다.
  • generator는 iterator 이고 yield로 실행을 멈추고 next() 로 실행을 계속한다.

차이점

  • async/await는 비동기 스타일을 동기처럼 처리하기 위해서 사용
  • promise는 then, catch, finally 로 콜백을 받아서 처리 할수 있고, race, all등 방법으로 비동기를 처리한다.

Promise중 then 두번째 argument 와 catch 차이점이 무엇인가요?

getBoundingClientRect와 getClientRects의 차이점은 무엇인가요?
  • getBoundingClientRect(): 요소 하나의 크기와 뷰포트 기준 위치(top/left/right/bottom/width/height)를 담은 DOMRect 객체 하나를 반환한다. 요소가 여러 줄(inline)에 걸쳐 있어도 전체를 감싸는 하나의 사각형만 알려준다.
  • getClientRects(): 요소를 렌더링하는 데 사용된 각 사각형(줄바꿈된 inline 요소라면 줄마다 하나씩)의 목록을 DOMRectList로 반환한다. 즉 getBoundingClientRect는 이 목록 전체를 감싸는 경계 상자와 같다.

사용자 인증을 어떻게 하나요?

대표적으로 세 가지 방식이 있습니다.

  • Session-Cookie: 서버가 로그인 성공 시 세션을 생성해 저장하고, 클라이언트에는 세션 ID만 쿠키로 내려준다. 이후 요청마다 쿠키를 자동으로 전송해 서버가 세션 저장소를 조회해 사용자를 식별한다.
  • Token(JWT 등): 서버가 사용자 정보를 담은 토큰을 발급하고, 클라이언트가 매 요청마다 Authorization 헤더 등에 토큰을 담아 보낸다. 서버는 별도 저장소 조회 없이 토큰 서명만 검증하면 되므로 확장(scale-out)에 유리하다.
  • SSO(Single Sign-On): 여러 서비스(도메인)를 하나의 인증 서버로 통합해, 한 번 로그인하면 다른 서비스에서도 재로그인 없이 인증 상태를 공유하는 방식이다. OAuth2, SAML 등을 기반으로 구현한다.

OSI(Open Systems Interconnection) 7 계층은?

OSI 모델은 7개의 계층으로 나뉩니다. 각 계층은 네트워킹 스택 내에서 중요한 역할을 수행하며 PDU(Protocol Data Unit)를 교환하여 다른 계층과 통신합니다.

  1. 물리적 계층(物理层)

    원시 비트스트림이 물리적 매체를 통해 물리적으로 전송되는 곳

  2. 데이터 링크 계층(数据链路层)
    1. 물리 계층에서 전송하기 위해 프레임으로 전송할 데이터를 분할
    2. 연결 설정, 물리적 계층에서 발생하는 비트 오류 식별 및 수정
    3. 세션이 완료되면 연결 종료를 포함하여 서로 다른 두 노드 간의 연결을 관리
  3. 네트워크 계층(网络层)

    네트워크 계층 디바이스는 패킷에서 작동하며 IP 주소를 기반으로 트래픽을 대상으로 라우팅하는 역할

  4. 전송 계층(传输层)

    데이터가 올바른 순서로 도착하고 오류가 수정되도록 하는 것을 포함하여 노드 간의 데이터 전송을 관리(TCP, UDP)

  5. 세션 계층(会话层)

    세션 관리에는 설정, 인증, 종료 및 재연결이 포함

  6. 프레젠테이션 계층(表示层)

    네트워크 데이터의 데이터를 애플리케이션에 필요한 형식으로 변환하는 작업을 담당

  7. 애플리케이션 계층(应用层)

    애플리케이션을 위한 서비스 제공(http, https, ftp, smtp등등)

TCP/IP 와 OSI 관계가 어떻게 되나요?

OSI 모델은 하나의 네트워킹 모델일 뿐입니다. 다른 하나는 OSI 모델보다 앞서고 네트워킹 스택을 구현하는 프로토콜에 더 가깝게 매핑되는 TCP/IP 모델입니다.

OSI 모델은 보다 이론적이며, 애플리케이션 계층 데이터를 전기, 빛 또는 전파를 통해 전송하기 위해 수행해야 하는 다양한 작업을 설명합니다. TCP/IP 모델은 보다 실용적이며 실제 네트워크 프로토콜에 가깝게 매핑됩니다.

TCP와 UDP의 차이점
  • 연결지향성
    • TCP는 연결 지향적 프로토콜이고 UDP는 연결 지향적이지 않은 프로토콜입니다.
  • 신뢰성
    • TCP는 데이터 전송 중 오류가 발생하면 재 전송을 통해 정확성과 순서를 보장합니다.
    • UDP는 신뢰성이 낮지만 실시간 스트리밍 게임 등 빠른 전송이 필요한 경우에 사용됩니다.
  • 헤더 오버헤드
    • TCP는 헤더의 크기가 크며 핸드쉐이킹 정보, 순서 번호, 오류제어 매커니즘 등의 추가 정보를 포함합니다.
    • UDP는 헤더의 크기가 작습니다.
  • 속도
    • TCP는 UDP에 비해서 느리다.
  • 멀티캐스트, 브로드캐스트
    • TCP는 멀티캐스트, 브로드캐스트를 지원하지 않고 UDP는 지원합니다.
TCP, UDP 사용 범위
  • TCP(효율은 낮지만 정확성을 요구하는 환경)
    • 웹브라우징, 이메일 전송, 파일전송, 원격 로그인 등등
  • UDP는 (빠른 전송이 필요한 환경)
    • 실시간 스트리밍, 게임, DNS조회, 멀티캐스트 등등
TCP의 흐름 제어(Flow Control)와 혼잡 제어(Congestion Control)는 어떻게 동작하나요?

TCP는 신뢰성 있는 전송을 위해 흐름 제어와 혼잡 제어를 함께 사용한다.

흐름 제어(Flow Control) — 수신 측 처리 속도가 송신 측보다 느릴 때 수신 버퍼가 넘치는 것을 막는다.

  • Stop and Wait: 세그먼트 하나를 보낼 때마다 ACK를 기다린 뒤 다음 세그먼트를 전송한다.
  • Sliding Window: 수신 측이 자신의 수신 가능 버퍼 크기(윈도우 크기)를 ACK에 실어 알려주고, 송신 측은 그 범위 내에서만 밀어넣듯 여러 세그먼트를 연속 전송한다.

혼잡 제어(Congestion Control) — 네트워크 경로 자체가 감당할 수 있는 양보다 많은 데이터가 몰려 성능이 저하되는 것을 막는다. cwnd(congestion window), ssthresh(slow start threshold) 값으로 전송량을 조절한다.

  • 느린 시작(Slow Start): cwnd = 1에서 시작해 ACK를 받을 때마다 cwnd를 2배로 늘린다.
  • 혼잡 회피(Congestion Avoidance): cwnd가 ssthresh에 도달하면 배수 증가 대신 1씩 선형으로 증가시켜 폭주를 억제한다.
  • 빠른 재전송 / 빠른 회복(Fast Retransmit / Fast Recovery): 동일한 ACK를 3번 중복 수신하면 타임아웃을 기다리지 않고 즉시 재전송하며, ssthresh와 cwnd를 절반으로 줄인 뒤 혼잡 회피 모드로 전환한다(느린 시작으로 되돌아가지 않는다).

정리하면 cwnd < ssthresh이면 느린 시작, cwnd ≥ ssthresh이면 혼잡 회피 상태이며, 타임아웃으로 손실이 확인되면 ssthresh = cwnd/2, cwnd = 1로 초기화하고 다시 느린 시작을 수행한다.

  • SYN Synchronization
  • ACK Acknowledgement
  • RST Reset
  • PSH Push

  • FIN Finish

기타 (14)

AI 도구에서 어떻게 입/출력 하는 JSON을 보장하나요?

AI Agent의 JSON은 LLM이 스스로 100% 보장하는 것은 아닙니다. LLM은 확률 기반 모델이기 때문에 같은 질문이라도 출력이 달라질 수 있습니다.

그래서 실제 서비스에서는 REST API처럼 LLM을 신뢰하는 것이 아니라, Schema를 신뢰하는 구조로 설계합니다.

Tool이나 Function을 JSON Schema로 정의하고, LLM은 그 Schema에 맞는 arguments만 생성합니다. 이후 런타임에서 Schema Validation(Zod, JSON Schema 등)을 수행하고, 검증을 통과한 경우에만 실제 Tool이나 API를 실행합니다.

만약 Validation에 실패하면 재시도(Retry)하거나 오류를 반환하기 때문에, 비즈니스 로직은 항상 검증된 데이터만 처리하게 됩니다.

즉, AI는 자연어를 구조화된 데이터로 변환하는 역할을 하고, 데이터의 정확성과 안정성은 시스템이 보장하는 구조라고 생각합니다.

"REST API는 서버가 계약을 보장하지만, AI Agent는 Schema Validation이 계약을 보장합니다.”
그래도 AI가 틀리면 어떡하나요?

그래서 AI는 비즈니스 로직을 직접 수행하지 않습니다.

예를 들어 "주문을 취소해줘"라고 사용자가 말하면, LLM은 orderId와 reason 같은 구조화된 데이터를 생성할 뿐입니다.

실제 주문 취소는 기존의 REST API나 서비스 로직이 수행합니다.

따라서 AI는 의사결정자가 아니라 입력을 해석하는 역할만 하고, 중요한 비즈니스 검증은 기존 시스템이 담당합니다.

canvas 랑 webgl 차이점이 무엇인지?

canvas는 2D기반으로 작성되고 javascript로 처리 가능하다.

WebGL은 3D 기반으로 작성 되고 OpenGL ES과 같은 그패픽 프로그래밍 관련 기술이 필요하다.

Electron에 대한 이해
  • 크로스 플랫폼: windows, mac, 리눅스 같은 OS에서 잘 실행 된다.
  • 유연성: 다양한 시스템 관련된 API를 제공 한다.
  • 생태계: 오픈 소스이고 생태계가 잘되어 있다. Slack, vscode등등 성공사례
  • 성능이슈: node랑 Chromium동시 실행하다보니 구동이나 메모리 점유율에서 불리하다.
Electron중 메인 스레드랑 render스레드 가 각각 무엇인가요?
  • 메인 스레드는 프로그램 entry이고 모든 화면 관리하고 시스템 자원을 방문한다. 대부분 nodejs스레드이다.
  • render스레드는 주로 웹페이지를 보여주고 javascript를 통해서 webAPI에 접근 가능하다.
  • 통신은 IPC(Inter-Process Communication)， BrowserWindow를 통해서 진행한다.
JSON, XML의 차이가 무엇인가요?

Javascript Object Notation 은 데이터 포맷이고 Extensible Markup Language 는 마크업 언어 입니다.

마이크로 프론트엔드가 무엇인가요?

일종 프론트엔드애서 사용하고 있는 웹개발 아키텍처 방식이고 여러개 작은 웹들이 모여서 한개 웹을 형성한다.

SPA페이지의 규모가 커짐에 따라서 운영이나 유지보수가 어려워 지는 경우가 있다보니 각 기능별로 구분해서 관리한다.

  • 각 작은 웹마다 독립적으로 실행, 개발, 배포 된다.
  • 기술 스택에 영향을 받지 않는다.
  • 필요한 부분만 버전업 가능하다
  • 프로젝트 규모가 커져도 빌드나 배포에 영향을 주지 않는다.
